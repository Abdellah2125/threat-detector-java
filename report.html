١. الملخص التنفيذي ونتيجة المراجعة

Threat Detector هو تطبيق سطح مكتب مستقل بلغة Java/JavaFX لفحص الروابط والرسائل وفق قواعد محلية حتمية، مع دعم الإدخال المفرد والدفعي عبر CSV، ومحرك فحص متعدد الخيوط، وعرض تقارير ودرجات ومستويات خطورة، وحالة مستقلة Not Verified عند تعذّر التحقق (ولا تُعامل كـ "آمن").

17قاعدة كشف محلية 4عمال كحد أقصى 52اختبارًا ناجحًا 0اتصال شبكي فعلي
نتيجة المراجعة: متطلبات Sprint 01 الأساسية مُحققة وظيفيًا في التنفيذ الحالي (Option A مُفعّل، إدخال مفرد/دفعي، فصل معماري، عرض النتائج والتقدم، استجابة الواجهة، ومعالجة الأخطاء مع Not Verified). ميزة AI اختيارية جزئية/هيكلية (طبقة ثانوية قابلة للتوصيل ولا تغيّر الدرجة). توجد ملاحظات تحسين غير حاجبة (مثل كود UI غير مستخدم، وبعض تفاصيل عرض)، موثقة في قسم المراجعة.

شهدت الواجهة مؤخرًا إعادة تنظيم (شريط علوي، صفحات Dashboard/History/Settings، سجل جلسة، وتبديل ثيم داكن/فاتح) مع الحفاظ على منطق الكشف والتشغيل. كما أُزيلت صفحة Hardware وعُناصرها الخاصة بالتصوير ثلاثي الأبعاد من الشيفرة الحالية.

5 عرض مؤشرات تقدم لكل عملية تقييم. ScanProgress (شريط تقدم وعدّاد وحالة عامل) مدمج في CheckPanel وBulkPanel؛ حالة حيّة في TopNav؛ تدفق أحداث ScanEvents/ScanObserver → ScanUiBridge مع Platform.runLater. مُحقق
6 واجهة مستجيبة وسهلة الاستخدام. تنفيذ الفحص على خيوط خلفية (check-scan/batch-scan)، تحديثات UI عبر خيط JavaFX، تخطيطات قابلة للتمدد/التمرير، حد أدنى للنافذة (1024×640)، جداول وبطاقات واضحة، تبديل أوضاع وتنقل. مُحقق
7 معالجة الإدخال والأخطاء: فراغ، URL مشوه، صفوف CSV غير صالحة، ملفات مفقودة، واستجابات API غير متاحة دون انهيار. RuleSet: EMPTY_INPUT/INVALID_URL/INPUT_TOO_LONG → NotVerified. CsvLoader: ملف مفقود/حجم/ترميز/رأس/لا صفوف → LoadException؛ صفوف غير صالحة تُحفظ كـ NotVerified(INVALID_CSV_ROW). ExternalApiEvaluationService (محاكاة) وScanEngine يعزلان CheckUnavailableException/الاستثناءات إلى NotVerified دون إسقاط الدفعة. مُحقق
8A Option A (قواعد محلية): فحص بنية URL ومحتوى الرسائل، وتجميع الدرجات إلى Low/Medium/High. LocalRuleEvaluationService + RuleSet: 10 قواعد URL و7 قواعد رسالة (17)، تطبيع/تحقق المدخل، تجميع نقاط وقصّ عند 100، تصنيف 0–24 LOW, 25–59 MEDIUM, 60–100 HIGH عبر Scoring. مُحقق (الخيار المعتمد)
8B Option B (API خارجي): اتصال بخدمة استخبارات تهديد مع معالجة 429/timeout/missing key/invalid response. ExternalApiEvaluationService يَنمذج جميع حالات الفشل المطلوبة ويرمي CheckUnavailableException لتتحول إلى NotVerified. لا يوجد طلب HTTP فعلي (بناء Offline مقصود)؛ لذلك التنفيذ نمذجة/جاهزية معمارية وليس تكاملاً حيًا. جزئي/نمذجي
9 الفحوص غير القابلة للإكمال يجب أن تُبلّغ كـ "Not Verified" (ولا تُفترض "Safe"). ScanOutcome.NotVerified نوع/حالة مستقلة؛ ScanEngine وRuleSet وCsvLoader تستخدمها للأخطاء/عدم التحقق؛ الواجهة تعرضها صراحة وتعتبرها غير محسوبة/غير آمنة. مُحقق
Bonus تكامل AI اختياري لشرح/تصنيف ثانوي، يفشل بلطف ولا يغيّر الدرجة. AiExplanationService يعيد Optional.empty() عند عدم التوفر أو لنتائج غير محسوبة، ويولّد شرحًا بسيطًا عند التوفر؛ ScanCoordinator يمرره للعرض الثانوي دون تغيير الدرجة. غير موصول بنموذج فعلي. جزئي (هيكلي)
خلاصة المطابقة: المتطلبات الإلزامية لـ Sprint 01 مُلبّاة عبر Option A المحلي مع المعالجة الصحيحة لحالات عدم التحقق والتزامن وعرض التقدم. Option B وAI متوفران كبنية/نمذجة داعمة وليسا تكاملات خارجية حية في هذه النسخة.

٤.٢ تدفق الفحص المفرد

  1. المستخدم يختار URL/Message ويُدخل النص (أو مثال) في CheckPanel.
  2. تحقق UI (فراغ/حد طول) ثم تشغيل خيط check-scan واستدعاء ScanCoordinator.scanSingle.
  3. ScanEngine يوزع عنصرًا واحدًا على عامل (≤4) ويستدعي ThreatEvaluationService (افتراضيًا LocalRuleEvaluationService).
  4. RuleSet يطبع/يتحقق المدخل، يشغّل القواعد، وScoring يصدر Scored أو NotVerified.
  5. الأحداث تُجسر عبر ScanUiBridge إلى TopNav/ScanProgress/ResultsSection/SummaryCard/RecentHistoryCard/HistoryPanel.

٤.٣ تدفق الفحص الدفعي (CSV)

  1. BulkPanel يفتح الملف عبر FileChooser ويحمّله بـ ScanCoordinator.loadCsv → CsvLoader.
  2. ينتج CsvLoadReport (صفوف صالحة + صفوف غير صالحة موسومة مسبقًا NotVerified/INVALID_CSV_ROW + تحذيرات).
  3. ScanCoordinator.scanBatch يلفّ المقيّم لإعادة النتائج المسبقة دون إعادة تقييمها، ويمرر العناصر إلى ScanEngine.
  4. تُعرض النتائج في تقرير دفعي (ملخص/توزيع/فلاتر/جدول) ويُضاف كل عنصر إلى السجل.

٥. منهجية الكشف والتقييم (Option A/B والدرجات)

٥.١ Option A (المعتمد فعليًا)

  • تنفيذ محلي كامل في detection/* عبر LocalRuleEvaluationService → RuleSet.
  • التحقق/التطبيع: إدخال فارغ → EMPTY_INPUT؛ حدود طول 2048 (URL) و5000 (رسالة) → INPUT_TOO_LONG؛ URL يُضاف له https:// عند غياب المخطط، ويُقبل http/https فقط مع مضيف صالح وإلا INVALID_URL.
  • 17 قاعدة: 10 URL (url.no_https, url.ip_host, url.userinfo, url.punycode, url.many_subdomains, url.suspicious_tld, url.shortener, url.nonstandard_port, url.long_url, url.bait_keywords) و7 رسائل (msg.urgency, msg.credential_request, msg.financial_bait, msg.threat_pressure, msg.shortened_link, msg.callback_request, msg.all_caps).
  • الدرجات: مجموع نقاط النتائج، قصّ إلى [0,100]، تصنيف HIGH ≥ 60، MEDIUM ≥ 25، وإلا LOW (منخفض ≠ آمن).

٥.٢ Option B (نمذجة حالات عدم التوفر)

ExternalApiEvaluationService يطرح CheckUnavailableException في الأوضاع: MISSING_KEY, RATE_LIMITED, TIMEOUT, INVALID_RESPONSE, AVAILABLE (الأخير غير متاح عمدًا في البناء غير المتصل) بأكواد API_KEY_MISSING / API_RATE_LIMITED / API_TIMEOUT / API_INVALID_RESPONSE / CHECK_UNAVAILABLE، ليحوّلها المحرك إلى NotVerified. لا يوجد عميل HTTP فعلي.

٥.٣ طبقة AI (اختيارية/ثانوية)

AiExplanationService(available): عند عدم التوفر أو لغير Scored يعيد فارغًا؛ عند التوفر يعيد شرحًا نصيًا مبنيًا على النتائج دون تعديل الدرجة.

٧. التشغيل والتزامن والأحداث

  • المحرك: ScanEngine بمسبح ثابت Executors.newFixedThreadPool، عدد عمال = min(maxWorkers, max(1,total)) و0 للعناصر الفارغة. DEFAULT_WORKERS=4.
  • التوزيع: AtomicInteger cursor يسلّم كل عنصر لعامل واحد؛ AtomicInteger completed لتتبع التقدم.
  • الترتيب: النتائج تُكتب في مصفوفة بحسب الفهرس الأصلي وتُعاد مرتبة رغم اكتمال غير مرتب.
  • العزل: CheckUnavailableException → NotVerified(code,msg)؛ أي Throwable آخر → NotVerified(RULE_EXCEPTION,...)؛ فشل عامل في Future.get يُقاطع ويطرح IllegalStateException.
  • الإغلاق: انتظار المهام، shutdown، انتظار 5 ثوانٍ ثم shutdownNow عند الحاجة.
  • الأحداث: ScanEvents (Started/Item/Finished)، ScanObserver (ردود افتراضية + NO_OP)،Callbacks قد تعمل على خيوط العمال؛ الواجهة تُحدّث عبر Platform.runLater في ScanUiBridge/ScanProgress.
  • القياس: زمن العنصر والتقرير بـ nanoTime مع حد أدنى 1ms للعرض.
  • ملاحظة تنفيذية: معرّف الفحص في أحداث/تقارير المحرك مضبوط حاليًا إلى 0 ولا يُستمد من ScanCoordinator.scanIds (لا تأثير وظيفيًا على المتطلبات الحالية).

٩. معالجة الأخطاء ودلالة Not Verified

الكود/الحالةالمصدرالمعنى/السلوك
EMPTY_INPUTRuleSetمدخل فارغ بعد الاقتطاع → Not Verified.
INVALID_URLRuleSetمخطط غير مدعوم/مضيف مفقود/URI غير صالح → Not Verified.
INPUT_TOO_LONGRuleSetتجاوز حد طول URL/Message → Not Verified.
INVALID_CSV_ROWCsvLoaderنوع غير مدعوم أو هدف فارغ في صف CSV → Not Verified (يبقى ضمن النتائج).
LoadExceptionCsvLoaderفشل فتح/قراءة/التحقق البنيوي للملف (مفقود، حجم، ترميز، رأس، بلا صفوف) → إيقاف التحميل مع رسالة.
API_KEY_MISSING / API_RATE_LIMITED / API_TIMEOUT / API_INVALID_RESPONSE / CHECK_UNAVAILABLEExternalApiEvaluationServiceفشل/عدم توفر تحقق خارجي (نمذجي) → Not Verified.
RULE_EXCEPTIONScanEngineاستثناء غير متوقع أثناء تقييم عنصر → عزل كـ Not Verified دون إسقاط الدفعة.
قاعدة أساسية: Not Verified تعني تعذّر التحقق/عدم اكتمال الفحص، وليست "آمنًا" ولا تُحوّل إلى LOW. الواجهة والنماذج تميز هذه الحالة صراحة.
